# 代码质量 Checklist

> 每次修改代码前必须逐条过。全部打勾才算完成，才能告知祥哥。

---

## 修改前（方案阶段）

```
[ ] 是否理解了问题根因？（不是症状）
[ ] 改动范围是否明确？（列文件清单）
[ ] 一次改动的文件 ≤ 3 个？超过则拆分
[ ] 是否知道怎么验证它？（具体命令/操作）
```

## 修改中（执行阶段）

```
[ ] 每改完一个逻辑单元，停下来验证一次
[ ] 改动的文件是否都用 auto() 包裹了？（如果读 store）
[ ] 新组件是否需要 import 样式文件？
[ ] useEffect 依赖项是否在 render 体读取的？
[ ] 替换旧组件时，是否 grep 了所有引用它的地方？
```

## 修改后（验证阶段）

```
[ ] 能启动，无报错？（npm run app 或等价的启动命令）
[ ] 能跑通基本功能？（手动操作，确认改动生效）
[ ] 不相关的功能是否被破坏了？（回归检查）
[ ] 改动涉及的所有路径都测了？（如：开/关、显/隐、真/假分支）
```

## 交工前（完成阶段）

```
[ ] 前三阶段 checklist 全部打勾
[ ] PROGRESS.md 已更新
[ ] 已执行 xnow sync（提交+推送）
```

## 反模式（禁止行为）

- ❌ 一次改超过 3 个文件而不拆分步骤
- ❌ 改完不验证直接让祥哥验收
- ❌ 猜测根因后批量修改多个可能原因
- ❌ 改完不检查不相关功能是否被破坏
- ❌ 没有 feedback loop 就开始修 bug
